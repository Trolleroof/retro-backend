# BC join logic port — status

Tracking [retro-backend#33](https://github.com/adavyas/retro-backend/issues/33): port the observation→control→outcome
join logic from [tui-gamepigeon's `bc-export.ts`](https://github.com/Trolleroof/tui-gamepigeon/blob/main/packages/trace-export/src/bc-export.ts)
so the Parquet generator here has the same semantics as `extractBehaviorCloningSamples()`.

## Status: ported

[tui-gamepigeon#167](https://github.com/Trolleroof/tui-gamepigeon/issues/167) landed, extracting
`@tui-games/trace-export` to `packages/trace-export`. retro-backend's Worker is Python (Pyodide), so the npm package
isn't consumable at runtime — chosen option is **copy with a golden test** (issue #33's option 2), not a runtime
dependency on `@tui-games/trace-export`.

- Ported to [`src/retro_backend/services/bc_export.py`](../src/retro_backend/services/bc_export.py):
  `extract_behavior_cloning_samples()` (join across chunks, `actors`/`include_noops` parity) and `split_for_game()`
  (same FNV-1a bucket hash).
- Golden test: [`tests/test_bc_export.py`](../tests/test_bc_export.py) against
  [`tests/fixtures/bc_export_golden.json`](../tests/fixtures/bc_export_golden.json), which was generated by running
  the actual `extractBehaviorCloningSamples()`/`splitForGame()` from `packages/trace-export` (via `bun`) against the
  same scenarios as its own `bc-export.test.ts` — so the fixture is the TS implementation's real output, not a
  hand-written guess.
- `include_noops` and `actors` flags preserved for parity (default `actors = {"human"}`, matching the TS default).
