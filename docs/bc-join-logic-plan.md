## Known porting hazard: game_id ordering

`orderedUniqueEvents` sorts with `left.game_id.localeCompare(right.game_id)` — ICU collation, not code-point order.
Over the alphabet `GAME_ID_PATTERN` allows (`^game_[A-Za-z0-9._-]+$`) that means `_` < `-` < `.` < digits < letters,
compared case-insensitively first with case only breaking ties. Python's native `str` ordering is code-point order
and disagrees (`game_A1` vs `game_a1` vs `game_a_b`), so `bc_export._game_id_sort_key()` reproduces the ICU weights
explicitly.

This is not cosmetic. The observation/outcome/ruleset lookups are last-write-wins over the sorted event order, so
when an `observation_id` is reused across games the ordering decides which sample is emitted at all — see
`test_shared_observation_id_resolves_by_collation_order`. Characters outside the contract alphabet fall back to
code-point order and are not guaranteed to match `localeCompare`.

Two remaining differences are deliberate: the TS yields `null`/`undefined` where the Python raises `KeyError` when a
chunk omits `game_type` or an `episode_started` payload omits `ruleset_id`. Both fields are required by
`TraceEventChunk`/`EpisodeStartedTraceEvent`, so that input violates the shared schema either way.
